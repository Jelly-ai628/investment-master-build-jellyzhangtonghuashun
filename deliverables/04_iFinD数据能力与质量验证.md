# iFinD 数据能力与质量验证

日期：2026-10-07。范围：指数/板块服务的实际工具 schema、4次只读数据查询、1次扶摇行情对照，以及可复用的响应校验代码。没有调用 DeepSeek，没有将原始供应商数据发给其他模型。

结论：**iFinD 数据调用通路可用，但返回内容不能直接成为已验证证据。** 已取得少量历史指数行情、PE/PB和部分市场指标；单位、日期参数、缺失字段和数据精度问题需要逐项处理。完整 P0 和市场研究主链路仍未完成。

## 1. 实际发现的三个工具

| 工具 | 真实 schema | 本次使用与限制 |
|---|---|---|
| index_data | query 字符串；要求指数、信息、明确起止日期 | 实际查询沪深300 20260928–20260930行情与估值，再查询20260831单日 |
| sector_data | query 字符串；要求板块实体、分类、信息、时间 | 实际查询全部A股20260930市场宽度与成交额，再明确追问绝对家数 |
| index_highfreq_quotes | symbols、indicators、data_mode 必填，interval 可选 | 仅支持交易日日内，不支持历史查询；本次历史样本不调用此工具 |

高频工具还有一个文档不一致：描述中的例子使用 `realtime`，真实枚举为 `real_time` / `highfreq`，以后必须按 schema 校验，不能照抄描述示例。

指数/板块工具实际返回 MCP text 内容，内部是 JSON，`data.answer` 为 Markdown 表格，`indicators_params` 为指标参数。它不是稳定的数值数组。观察到内部业务成功为 **code=1**，不同于扶摇的 code=0；MCP isError=false 本身也不能证明字段满足研究要求。

## 2. 真实查询与结果

| 查询 | 返回情况 | 结论 |
|---|---|---|
| 沪深300，20260928–20260930，收盘、PE TTM、PB | 返回3行历史日期及对应数值 | 数据通路可用；指数收盘单位写成元，历史指标参数却出现“最新” |
| 全部A股，20260930，上涨/下跌/平盘/停牌家数、成份数、成交额 | 返回上涨占比、跌停数量、成交额、成份数 | 所需四类家数未取得，不能拿占比或跌停数替代 |
| 沪深300，20260831，明确要求固定历史日期和点数单位 | 返回另一历史日期；PE参数变为指定日期，PB仍出现“最新”，收盘仍标元 | 改善了部分日期参数，但单位与PB口径仍未解决；不是再次盲重试同一请求 |
| 全部A股，20260930，明确只要绝对涨跌/平盘/停牌家数 | 仍只返回上涨占比，参数为“最新” | 本工具此次查询未能满足家数要求，不继续重复请求，也不宣称供应商所有接口都不支持 |

“历史表格 + 最新参数”是证据冲突，不据此断言表格数值一定来自最新日期，也不能忽略参数直接断言已满足历史研究。PE TTM 基准、PB MRQ 匹配和“不调整”说明已保留，但指数聚合方式、单位与历史时点仍需核验。三日/单日样本不足以计算长期估值分位。

成交额以带“万亿”后缀的展示文本返回。代码可以规范换算，但原始精度已经被展示格式限制，应保存原文和精度标记，不能把换算后的长整数当作精确原始金额。

全部A股名称虽然返回“内地股票->股票市场类->全部A股”，本次未取得足以核对沪深北具体覆盖、停牌纳入规则和上涨占比分母的完整定义。不得直接把它标为已确认的沪深北全市场宽度。

## 3. 扶摇对照验证

对同一指数、同样三个日期，从扶摇另取历史日线，逐日比较收盘值：**3/3在扶摇两位小数精度下相符**。最大原始差值为0.005，按十进制定点四舍五入核对。

这支持该三日指数收盘数值的一致性，不修复 iFinD 的单位标签，也不证明其PE/PB和日期参数正确。两者都属于同花顺体系，不算两个独立信息来源。

运行时建议继续采用扶摇已验证的结构化指数行情；iFinD 的估值和市场指标先作为待核实数据候选。市场宽度另以扶摇全市场快照的完整分页与样本核对进行建设，不能用当前不匹配的 iFinD 返回值凑齐。

## 4. 已实现的校验与证据保留

代码：[ifind_contract.py](../apps/api/market_research/ifind_contract.py)。它只支持本次观察到的单张标准 Markdown 表格响应，未知格式明确报错，不尝试猜测解析。

- 分别检查 MCP isError、内部业务 code、子错误和数据结构。
- 核对标的、日期集合、重复日期、表格列数、唯一字段名。
- 按所需字段的准确名称匹配；上涨占比不匹配上涨家数，跌停数不匹配下跌数。
- 保留原始单元格、表头、数据行号、指标参数、原报单位与预期单位；不静默纠正“元”为“点”。
- 日期参数为“最新”、缺少参数、参数未被验证或单行日期与指定参数冲突时，不将对应单元格作为已验证证据。
- 严格解析数字，区分缺失与零、展示缩放与原始精度；数量必须为非负整数，指数点数必须为正。
- 每条候选返回 `eligible_for_claim` 和具体 issues；一张表返回 success 不会自动批准整表。

本次4个响应经检查均为 `needs_review`，没有自动放行到市场结论。原始响应只保存在已忽略的本地 `work/`，交付文档只记录能力与质量判断。

本地复核命令：

```bash
uv run python scripts/validate_ifind_samples.py
```

该命令复核已保存样本，不发请求；缺少本地样本时明确退出。退出码0表示复核程序完成，是否可用应查看报告的 status 和逐项 issues，不能把退出码0当作数据验收通过。报告为 `work/ifind-data-quality-report.json`。

## 5. 测试与 AI 验证记录

执行 `uv run pytest -q --tb=short`，最终 **61 passed in 0.46s**。此前38项接入测试加本轮23项数据合同测试，均为本地构造响应，不依赖真实密钥或实时供应商状态。

新增测试覆盖：供应商成功码区别、占比误替代家数、历史参数写最新、指数单位错标、单位缺失/冲突、空值、展示缩放精度、模糊数字、不合法数量、日期错位、表格结构错误，以及空验证要求不得批准任意响应。

AI 在真实响应检查后新增了数据合同校验；自检进一步发现“固定日期参数可能错误批准同一表其他日期的行”，已加入逐行核对及回归测试。以上为AI自检与修正，没有记成用户人工修正。供应商返回数据中的问题被保留为待核实事项，没有直接修改原数据制造通过结果。
